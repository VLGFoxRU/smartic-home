# SmarticHome — Платформа для управления умным домом

**SmarticHome** — это полнофункциональная платформа для мониторинга и управления устройствами умного дома с элементами машинного обучения. Система включает в себя сбор телеметрии, детектирование аномалий, сценарии автоматизации и многофункциональный веб-интерфейс в стиле современных дашбордов.

## Возможности

- **Мониторинг в реальном времени:** сбор и визуализация телеметрии (температура, влажность, энергопотребление, расход воды).
- **Управление устройствами:** включение/выключение освещения, изменение яркости, управление розетками.
- **Сценарии автоматизации:** создание правил типа «если температура > 25°C, включить свет».
- **Детектор аномалий:** автоматическое выявление отклонений на основе статистических данных (среднее ± 3σ) и настраиваемых порогов.
- **Многопользовательность:** регистрация, роли (владелец, администратор, контроллер, наблюдатель), управление домами и членами семьи.
- **Аудит действий:** все изменения записываются в журнал аудита.
- **Гибкий веб-интерфейс:** дашборд с карточками домов и комнат, графики телеметрии, управление сценариями, тёмная/светлая тема, Toast-уведомления.
- **WebSocket-уведомления:** мгновенные оповещения о новых аномалиях и срабатывании сценариев.

## Архитектура

Текущая реализация представляет собой **монолит** с чётко разделёнными пакетами, готовыми к распиливанию на микросервисы.

```
┌──────────────────────────────────────────────────────────────┐
│                       Фронтенд (React)                       │
│  Дашборд | Комнаты | Графики | Сценарии | Аномалии | Профиль │
└────────────────────────┬─────────────────────────────────────┘
                         │ HTTP REST / WebSocket
┌────────────────────────▼─────────────────────────────────────┐
│                    API Gateway (Go)                          │
│  Аутентификация (JWT), маршрутизация, CORS                   │
└────────┬───────────┬─────────┬──────────────┬────────────────┘
         │           │         │              │
┌────────▼───┐ ┌─────▼────┐ ┌──▼──────┐ ┌─────▼──────┐
│ Device     │ │Control   │ │Telemetry│ │Scene/      │
│ Service    │ │Service   │ │Service  │ │Anomaly     │
└────────┬───┘ └─────┬────┘ └──┬──────┘ └─────┬──────┘
         │           │         │              │
┌────────▼───────────▼─────────▼──────────────▼────────────────┐
│                   Инфраструктура                             │
│  PostgreSQL (основная БД + TimescaleDB опционально)          │
│  Redis (кэш состояний, сессии)                               │
│  RabbitMQ / StubBroker (асинхронная передача команд)         │
│  WebSocket Hub (реал-тайм уведомления)                       │
└──────────────────────────────────────────────────────────────┘
```

### Внутренняя структура бэкенда

- **`internal/domain`** – доменные сущности (`Device`, `Scene`, `Anomaly`, `AlertThreshold`, `Home`, `Room`, `User`). Содержит бизнес-инварианты и методы переходов состояний.
- **`internal/repository`** – интерфейсы репозиториев (контракты для работы с БД).
- **`internal/infrastructure`** – реализации репозиториев под PostgreSQL, Redis, заглушку брокера и WebSocket-издатель событий.
- **`internal/service`** – бизнес-логика (сервисы `DeviceService`, `ControlService`, `TelemetryService`, `SceneService`, `AnomalyService` и др.).
- **`internal/handler`** – HTTP-обработчики (controllers), DTO.
- **`internal/middleware`** – CORS, логгирование, JWT-аутентификация.
- **`internal/engine`** – `SceneEngine` – автоматическое выполнение сценариев.
- **`internal/detector`** – `AnomalyDetector` – автоматический детектор аномалий.
- **`cmd/api`** – точка входа, конфигурация зависимостей вручную (DI).

## Установка и запуск

**Предварительные требования:** Docker Desktop, Node.js ≥ 20, Go ≥ 1.24 (для локальной разработки бэкенда).

### Бэкенд

1. Перейдите в папку `backend`:
   ```powershell
   cd backend
   ```
2. Скопируйте `.env.example` в `.env` и при необходимости измените пароли:
   ```powershell
   copy .env.example .env
   ```
3. Запустите все сервисы (PostgreSQL, Redis, API Gateway):
   ```powershell
   docker compose up --build -d
   ```
   Бэкенд будет доступен на `http://localhost:8080`.

### Фронтенд

1. Перейдите в папку `frontend`:
   ```powershell
   cd frontend
   ```
2. Установите зависимости:
   ```powershell
   npm install
   ```
3. Запустите dev-сервер:
   ```powershell
   npm run dev
   ```
   Фронтенд откроется по адресу `http://localhost:5173`. Все запросы к API проксируются на бэкенд (порт 8080).

## WebSocket-уведомления

Клиент может подключиться к `ws://localhost:8080/ws?token=<JWT>`. Сервер отправляет JSON-сообщения следующих типов:

- **`device.command_sent`** – отправка команды на устройство.
- **`telemetry.ingested`** – поступление нового показания телеметрии.
- **`anomaly.detected`** – обнаружение новой аномалии.
- **`scene.executed`** – срабатывание сценария.

Пример сообщения:
```json
{
  "type": "anomaly.detected",
  "payload": {
    "id": "uuid",
    "device_id": "uuid",
    "value": 35.0,
    "expected": 23.5,
    "severity": "critical",
    "timestamp": "2026-05-11T12:00:00Z"
  }
}
```

## Модель данных

### Основные таблицы

- **`users`** – пользователи (роли: owner, admin, controller, viewer).
- **`homes`** – дома (принадлежат владельцу).
- **`home_members`** – члены дома с ролями.
- **`rooms`** – комнаты (привязаны к дому).
- **`devices`** – устройства (типы: light, temperature_sensor, humidity_sensor, electricity_meter, water_meter, power_switch). Статусы: online, offline, disabled.
- **`device_states`** – текущие состояния устройств (JSONB, кэшируются в Redis).
- **`telemetry`** – временные ряды показаний (опционально TimescaleDB).
- **`anomalies`** – зарегистрированные аномалии (open → acknowledged → resolved / false_positive).
- **`scenes`** – сценарии автоматизации (draft → active / paused).
- **`alert_thresholds`** – пользовательские пороги оповещений (min/max + severity).
- **`audit_log`** – полный журнал действий пользователей и системы.

## Тестирование

- **Бэкенд:** интеграционные тесты на Go (testcontainers для PostgreSQL и Redis), юнит-тесты доменного слоя.
- **Фронтенд:** ручное тестирование по коллекции Postman, а также проверка всех UI-сценариев непосредственно в браузере.
- **Сквозной сценарий:** регистрация → создание дома → добавление комнат и устройств → отправка телеметрии → срабатывание детектора аномалий → выполнение сценария → проверка уведомлений в WebSocket.
